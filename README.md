# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

### Типы данных
В проекте используются следующие интерфейсы:

#### Интерфейс IProduct
Описание: Содержит информацию о товаре, представленном в каталоге. Имеет следующие свойства:

```typescript
interface IProduct {
  id: string;               // Уникальный идентификатор товара
  description: string;      // Описание товара
  image: string;            // Ссылка на изображение товара
  title: string;            // Название товара
  category: string;         // Категория товара 
  price: number | null;     // Цена товара 
}
```

#### Интерфейс IBuyer
Описание: Содержит информацию о покупателе. Имеет следующие свойства:
```typescript
interface IBuyer {
  payment: TPayment;        // Выбранный способ оплаты
  email: string;            // Адрес электронной почты покупателя
  phone: string;            // Телефон покупателя
  address: string;          // Адрес покупателя
} 
```

### События

#### События в слое «Модели»

`('productList:changed')` - событие генерируется при изменении каталога товаров.
`('product:selected')` - событие генерируется при изменении выбранного для просмотра товара.
`('cart:changed')` - событие генерируется при изменении содержиимого корзины.
`('buyer:changed')` - событие генерируется при изменении данных покупателя.
#### События в слое «Представления»

`('basket:open')` - событие генерируется при нажатии на кнопку открытия корзины.
`('modal:close')` - событие генерируется при нажатии на кнопку закрытия модального окна при успешном оформлении заказа.
`('basket:checkout')` - событие генерируется при нажатии на кнопку оформления заказа в корзине.
### Классы слоя «Модели» 

#### Класс ProductList
**Назначение:** Отвечает за хранение и управление списком всех доступных к покупке товаров, а так же товара выбранного для подробного отображения. Генерирует события при изменении списка или выборе товара, чтобы представления (Gallery, Modal) могли обновиться.

**Конструктор:**
`constructor(private events: IEvents)` - принимает в качестве параметра экземпляр брокера событий. Инициализирует пустой массив товаров и устанавливает значение previewItem в null

**Поля класса:**
`items: IProduct[]` - массив для хранения списка доступных товаров.
`previewItem: IProduct | null` - поле для хранения выбранного для просмотра товара.
`events: IEvents` - брокер событий подается в конструктор класса.

**Методы:**
`setItems(items: IProduct[]): void` - сохраняет переданный массив товаров, заменяя предыдущий список и генерирует событие `('productList:changed')`.
`getItems(): IProduct[]` - возвращает массив всех товаров.
`getItem(id: string): IProduct | undefined` - возвращает товар по его ID или undefined, если товар не найден.
`setPreviewItem(id: string): void ` - находит товар по ID и сохраняет его для детального просмотра и генерирует событие `('product:selected')`.
`getPreviewItem(): IProduct | null` - возвращает товар, сохраненный для детального просмотра.

#### Класс Cart
**Назначение:** Отвечает за хранение массива товаров, выбранных покупателем для покупки.Генерирует события при изменении содержимого корзины, чтобы представления (Header, Basket, Modal) могли обновиться.

**Конструктор:**
`constructor(private events: IEvents)` - принимает в качестве параметра экземпляр брокера событий. Инициализирует пустой массив товаров.

**Поля класса:**
`items: IProduct[]` - массив для хранения списка добавленных в корзину товаров.
`events: IEvents` - брокер событий подается в конструктор класса.

**Методы:**
`getItems(): IProduct[]` - возвращает массив товаров, которые находятся в корзине.
`addItem(item: IProduct): void ` - добавляет переданный товар в корзину и генерирует событие `('cart:changed')`.
`deleteItem(item: IProduct): void` - удаляет товар, переданный в качестве параметра, из корзины и генерирует событие `('cart:changed')`.
`clear(): void` - полностью очищает корзину и генерирует событие `('cart:changed')`. 
`getTotalPrice(): number` - вычисляет и возвращает общую стоимость всех товаров в корзине.
`getTotalQuantity(): number` - возвращает общее количество товаров в корзине.
`inCart(id: string): boolean` - проверяет наличие товара в корзине по указанному ID.

#### Класс Buyer
**Назначение:** Отвечает за хранение данных о покупателе уведомляет подписчиков о изменениях через события.

**Конструктор:** 
`constructor(private events: IEvents)` - принимает в качестве параметра экземпляр брокера событий. Инициализирует пустые поля класса.

**Поля класса:**
`payment: TPayment` - поле для хранения вида оплаты покупателя.
`email: string` - поле для хранения электронной почты покупателя.
`phone: string` - поле для хранения телефона покупателя.
`address: string` - поле для хранения адреса покупателя.
`events: IEvents` - брокер событий подается в конструктор класса.

**Методы:**
`setPayment(payment: TPayment): void` - сохраняет вид оплаты, переданный в качестве аргумента и генерирует событие `('buyer:changed')` с текущими данными покупателя.
`setEmail(email: string): void` - сохраняет электронную почту покупателя, переданную в качестве аргумента и генерирует событие `('buyer:changed')`.
`setPhone(phone: string): void` - сохраняет телефон покупателя, переданный в качестве аргумента и генерирует событие `('buyer:changed')`.
`setAddress(address: string): void` - сохраняет адрес покупателя, переданный в качестве аргумента и генерирует событие `('buyer:changed')`.
`getData(): IBuyer` - возвращаес все данные покупателя.
`clear(): void` - очистить все данные покупателя.
`validateStep1(): { payment?: string; address?: string }` - проверка типа оплаты и адреса. Возвращает объект с ошибками, если они есть.
`validateStep2(): { email?: string; phone?: string }` - проверка электронной почты и телефона. Возвращает объект с ошибками, если они есть.

### Класс коммуникационного слоя ProductAPI

**Назначение:** Отвечает за взаимодействие с сервером API. Получает данные о товарах и отправляет данные о заказах.

**Конструктор:**
- `constructor(api: IApi)` - принимает объект, соответствующий интерфейсу `IApi`

**Методы:**
- `getProductList(): Promise<IProduct[]>` - выполняет GET запрос на эндпоинт `/product/` и возвращает массив товаров
- `submitOrder(orderData: IOrder): Promise<IOrderResult>` - выполняет POST запрос на эндпоинт `/order/` и передает данные заказа. Возвращает объект с ID заказа и общей суммой.

**Формат данных:**
- **Отправляемые данные (IOrder):** содержат способ оплаты, контактные данные, адрес, общую сумму и массив ID товаров
- **Получаемые данные (IOrderResult):** содержат ID созданного заказа и общую сумму
